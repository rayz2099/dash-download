# 下载网页视频

更新桌面应用和扩展后，重新加载扩展并刷新网页。发布包内含媒体工具；源码开发需要先执行下方准备步骤。

## 使用

1. 在网页上播放视频。扩展自动嗅探当前标签页及内嵌播放器实际加载的 MP4、WebM、HLS、DASH 资源。
2. 点击右下角带数量的悬浮按钮，展开视频列表。默认下载最高画质，也可以点击“选择清晰度”读取并选择其他规格。HLS/DASH 默认保存为 MP4，可切换为 MKV。
3. 点击“下载”。应用未运行时尝试后台启动，添加成功显示“已添加”，不会拉起桌面主窗口。失败时显示原因并允许重试。
4. 在桌面应用管理进度、暂停、恢复和重新下载。保存位置使用默认下载目录，文件名优先采用视频元素标题，无标题时采用页面标题。

悬浮按钮与面板标题栏可以拖动。关闭后在当前标签页隐藏，通过插件工具栏弹窗的“视频资源”按钮恢复。扩展总开关同时控制下载接管和资源嗅探。

## 支持范围

| 资源 | 下载结果 | 说明 |
| --- | --- | --- |
| MP4 / WebM / MOV 文件 | 保留原文件格式 | 使用现有 HTTP 下载引擎 |
| 无 DRM 的 HLS / DASH 点播 | 默认 MP4，可选 MKV | 保留原编码、合并音视频；不自动转码，编码无法封装进 MP4 时可选择 MKV |
| 直播 | 提示暂不支持 | 不开始无限时长录制 |
| DRM 视频 | 提示暂不支持 | 不绕过播放授权 |

同一 X 视频的不同分辨率、播放清单按媒体 ID 归并。通用 HLS 主清单的子清单与已知分段会归并或隐藏；无法建立可靠关联的独立 URL 保持分开，避免误把不同视频合在一起。

嗅探不能保证覆盖所有网站：尚未加载的视频、纯内存生成且没有可识别网络资源的视频、失效的签名链接、额外设备绑定认证仍可能不可下载。遇到过期链接，可重新播放并刷新页面后再添加。普通 AES-128 HLS 不等于 DRM，支持范围由媒体工具实际解析结果决定。

选择分段流清晰度会通过桌面应用解析资源，因此可能后台启动应用。嗅探本身不会启动应用。浏览器在本次会话内保存每标签页的资源记录，关闭标签页后清除。

解析结果按 URL、请求上下文和代理配置隔离，在内存中复用 30 秒（最多 4 条）；下载进程直接读取已解析信息，避免重复解析清单。首次解析仍需网络请求，插件显示“解析中”。这不需要等待 Chrome 缓冲完整视频。MP4 合并会启用 faststart，便于从文件开头播放。

## 准备开发和发布环境

在仓库根目录执行（Python 3.9+）：

```sh
python3 -m venv /tmp/dd-media-tools-venv
/tmp/dd-media-tools-venv/bin/pip install imageio-ffmpeg==0.6.0
/tmp/dd-media-tools-venv/bin/python scripts/prepare-media-tools.py
```

Windows 可使用 `python -m pip install imageio-ffmpeg==0.6.0` 和 `python scripts/prepare-media-tools.py`。

脚本下载固定版本 yt-dlp（2026.08.19），验证官方 SHA-256，并复制 imageio-ffmpeg 0.6.0 提供的独立 FFmpeg。产物位于被 Git 忽略的 `crates/app/media-tools/`。macOS 使用官方目录版，避免单文件版每次解压运行库带来的重复启动检查。目录与许可证文件通过 Tauri resources 打包，发布工作流自动执行准备步骤。

运行时优先使用 `DD_MEDIA_TOOLS` 指定的目录、应用资源目录，再回退到 PATH；debug 构建也会查找仓库内准备的目录。没有工具时会明确报告错误，不把播放清单保存成伪视频文件。

任务类型、选定清晰度、请求上下文保存在现有 SQLite 任务库；重启后运行中的任务恢复为暂停。分段断点由 yt-dlp 管理，合并时不重编码。暂停会终止媒体进程及子进程，保留可恢复分段；被中断的最终合并文件会删除以便重新合并。

媒体工具不读取用户 yt-dlp 配置、插件目录或缓存，不通过 shell 执行。Cookie 写入短期、限定资源主机的 cookie 文件；Referer、User-Agent、Origin 通过短期配置传递，进程退出后删除。下载遵循桌面应用的代理设置。

## 验证

```sh
node --test extension/*.test.js
cargo test -p dd-core --lib
cargo test -p dd-core --test media_download -- --ignored
cargo check -p dd-app
```

`media_download` 需要已准备的媒体工具。测试自动生成带音轨视频，启动要求 Cookie 的本地服务器，验证 HLS 独立音轨、DASH、选定清晰度、探测阶段暂停/恢复、重名文件保存，并对最终文件完整解码。

浏览器实测需加载 `extension/`，打开带 `<video>` 的网页，检查自动出现、展开、清晰度、拖动、关闭和工具栏恢复。重新加载扩展后必须刷新测试网页。

2026-09-23 验证：用户提供的 X 帖子 `https://x.com/Lcxxx_Lee/status/2102449281663738286` 解析到 270p/360p/720p。在实际 X 页面通过悬浮窗点击下载，经 Native Messaging 交给正在运行的开发版应用，生成约 15.14 秒的 MP4，完整解码通过。HLS/DASH 的 MP4 与 MKV 输出均有本地集成测试覆盖。

该样例优化前每次清单解析约 2.9–3.4 秒；优化后首次约 3 秒，紧接着同 URL、请求上下文和代理下的解析约 0.2 毫秒。此数值是解析耗时，不是整个下载耗时。
